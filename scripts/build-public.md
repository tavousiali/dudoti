# راهنمای ساده `build-public.mjs`

## این اسکریپت چه کاری می‌کند؟

`build-public.mjs` نسخه عمومی سایت دودوتی را برای استقرار می‌سازد؛ یعنی نسخه‌ای که پنل ادمین در آن قرار ندارد.

مراحل آن به‌ترتیب:

1. پوشه‌های `src/app/AdminPanel` و `src/app/api/admin` را موقتاً به یک پوشه موقت خارج از پروژه کپی می‌کند و از مسیرهای برنامه کنار می‌گذارد.
2. با `npx prisma generate`، Prisma Client را برای محیطی که build در آن اجرا می‌شود می‌سازد.
3. با `next build`، نسخه قابل انتشار سایت را تولید می‌کند.
4. پوشه‌های ادمین را به محل اصلی‌شان برمی‌گرداند؛ چه build موفق شود و چه با خطا تمام شود.

در نتیجه، سورس پنل ادمین در مخزن حذف نمی‌شود؛ فقط در زمان ساخت نسخه عمومی از build کنار گذاشته می‌شود.

## چه زمانی اجرا می‌شود؟

تنظیم `vercel.json`، دستور `node scripts/build-public.mjs` را به‌عنوان دستور build پروژه معرفی کرده است. بنابراین وقتی Vercel برای پروژه build انجام می‌دهد، این اسکریپت اجرا می‌شود.

با اتصال GitHub به Vercel، این اتفاق معمولاً پس از push کردن کد به GitHub رخ می‌دهد: Vercel تغییرات را می‌گیرد، اسکریپت را اجرا می‌کند و اگر build موفق باشد نسخه را منتشر می‌کند. برای شاخه‌های دیگر ممکن است فقط نسخه Preview ساخته شود؛ رفتار دقیق به تنظیم شاخه‌ها در Vercel بستگی دارد.

## اجرای دستی روی کامپیوتر

برای اجرای همان build عمومی در ریشه پروژه:

```powershell
npm run build:public
```

این دستور همان اسکریپت را اجرا می‌کند. دستور `npm run build` مستقیماً `next build` را اجرا می‌کند و مراحل کنارگذاشتن موقت پوشه‌های ادمین را انجام نمی‌دهد؛ برای شبیه‌سازی build عمومی از `npm run build:public` استفاده کنید.

## نکته مهم

این اسکریپت فقط نحوه ساخت نسخه سایت را کنترل می‌کند؛ محتوای ذخیره‌شده در دیتابیس را ویرایش نمی‌کند و پنل مدیریت را آنلاین نمی‌کند. بعد از اتمام build، پوشه‌های ادمین در سورس پروژه برمی‌گردند، اما خروجی ساخته‌شده برای انتشار همچنان نسخه عمومی بدون پنل است.
